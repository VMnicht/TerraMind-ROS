# 导航板接入与坐标换算

`terramind_navigation_driver` 接收[导航串口协议 v1](navigation_output_protocol_v1.md)的固定 80 字节报文，输出原始快照、导航状态、局部位置姿态和 IMU 中心速度。协议副本来自板卡开发约定；其中 `TerraMind_FW` 链接指向发送端工程，不属于本 ROS 仓库。PC 接收实现不代表 H7 发送器已经完成。

## 启动

调试总面板选择“真实控制板”，勾选“同时接入导航板”。导航端口留空时使用选定 YAML 的 `device`；填写 `auto` 或路径时覆盖该字段。“选择 / 编辑”用于配置固定原点和安装外参，保存后重新启动后端生效。控制面板的“导航状态”页显示连接、质量、原点、外参及参考点；状态消息过期时明确显示不可用，不影响手动装置调试。

勾选 RViz 会显示 `navigation/pose` 和 `navigation/path`。轨迹按最多 10 Hz 抽样，保留最近 2000 点，重连或识别到板卡重启时清空。无效测量不增加轨迹点。RViz 中保留的位姿和轨迹是历史观察，实时可用性以导航状态页为准。

独立启动并加载指定配置及 RViz：

```bash
ros2 launch terramind_bringup navigation.launch.py config:=/绝对路径/navigation.yaml rviz:=true
```

配置内 `origin_mode: fixed` 使用填写的经纬度（度）和椭球高（米）；`first_valid` 原点显示在导航状态页，可将该原点抄入配置后改为 `fixed` 复用。外参平移单位米，旋转为 wxyz，标定完成后设置 `extrinsics_calibrated: true`。未标定时位姿参考点仍为 IMU。原点就绪不代表外参已标定，时间锁定也不代表 PC 已完成测量时钟同步。

联合入口支持 `navigation_config:=/绝对路径/navigation.yaml`、`navigation_device:=auto`（或 `/dev/...`）和 `navigation_rviz:=true`；端口覆盖优先级高于所选配置，其余参数从配置读取。

```bash
source scripts/native_gui_env.sh
source /opt/ros/humble/setup.bash
colcon build --packages-up-to terramind_navigation_driver terramind_bringup
source install/local_setup.bash
ros2 launch terramind_bringup navigation.launch.py device:=auto
```

与真实控制板一起启动：

```bash
ros2 launch terramind_bringup real.launch.py navigation:=true navigation_device:=auto
```

`real.launch.py` 默认 `navigation:=false`。导航默认 `device: auto`，以 460800 波特率被动监听候选串口，不发送探测字节。连续至少三帧协议格式/CRC 正确且序号向前推进，且最后推进帧仍新鲜时（按观测帧间隔的 1.5 倍判断，最短 150 ms、最长 1.5 秒），认为匹配；不要求定位有效或 RTK 固定。只有唯一匹配时连接，多个匹配会列出路径并等待手动指定。无设备、设备占用或拔插后按 `reconnect_interval_s` 重试；自动模式会重新枚举，适应 ttyUSB 编号变化。持续收到协议帧但定位无效时保持连接，作业可用性仍由原有定位门控判断。

`discovery_patterns` 默认包含 `/dev/serial/by-id/*`、`/dev/ttyUSB*`、`/dev/ttyACM*`，同一设备的别名去重；`discovery_listen_s` 默认 3.5 秒，以覆盖初始化/无定位时约 1 Hz 的三帧心跳；允许 0.15～10 秒。短窗口仅适用于已持续输出高频帧的设备。扫描会设置候选端口波特率，只应包含待识别的机器人串口。导航与控制板发现器使用同一用户的进程间扫描锁，整轮扫描互斥；已连接设备继续由设备锁保护。锁是本工程协作锁，不阻止不遵守该约定的外部串口程序。

手动填写 `/dev/serial/by-id/...` 或 udev 别名时只重连指定路径，不扫描其他设备。总面板导航端口留空使用 YAML，`auto` 或显式路径覆盖 YAML；配置的设备和实际连接路径见 `diagnostics` 中 `navigation_serial` 的 `configured_device` / `connected_device`。重连会更新会话并清空轨迹，保留当前进程原点和 PC 加载的外参；区域作业不会自动续跑。

配置见 `terramind_bringup/config/navigation.yaml`。直接加载自己的参数文件：

```bash
ros2 run terramind_navigation_driver navigation_serial_node --ros-args --params-file /绝对路径/navigation.yaml
```

配置在启动时读取，修改后重启节点生效。导航使用 460800、8N1、无流控，只读串口，不发握手、ACK 或控制字节。共享串口库仍支持原控制板的 115200，控制驱动自身仍强制 115200。

## 软件边界

| 文件 | 职责 |
|---|---|
| `protocol.hpp/.cpp` | 独立 CCITT-FALSE CRC、显式小端解码、有界流式组帧、数值校验 |
| `session.hpp/.cpp` | 在线/导航可用判断、序号缺口与回绕、重复历元、会话重建 |
| `coordinates.hpp/.cpp` | WGS84/ECEF/固定 ENU 正反变换，速度、四元数、安装外参 |
| `port_discovery.hpp/.cpp` | 被动识别唯一导航板，复用共享设备枚举与扫描锁 |
| `navigation_serial_node.cpp` | 独立工作线程接收、重连、参数、ROS 消息和诊断 |
| `navigation_test.cpp` | 协议固定向量、流解析、会话、坐标和安装方向单元测试 |
| `navigation_integration_test.py` | 独立 Python 编码器连接私有 PTY，验证实际 ROS 节点 |

核心库不依赖 ROS；坐标旋转使用 Eigen3，WGS84 计算采用 double。无需安装 GeographicLib。经纬度在公共 C++ 接口中用弧度；配置经纬度使用度，两者不能混用。

## 接收和有效性

- 每次串口读取可以含零帧、多帧或残帧。解包缓冲最多保留 79 字节残留；完整候选为 80 字节。
- CRC 覆盖偏移 `[2,78)`，初值 `0xFFFF`。控制板的 XMODEM CRC 初值为零，两个实现不混用。
- 版本/CRC 错误时只滑动一个字节；不提前跳过合法载荷内部的 `AA 55`。
- 候选首字节收到后计时，默认 100 ms 组帧超时；没有新数据也检查超时，不由后续分片续期。
- 校验正确的状态帧全部发布到 `navigation/raw`。`NAV_VALID=0`、故障、冲突标志、非有限数值、经纬越界或四元数范数不合格时不发布位姿/速度。
- 四元数平方范数与 1 的差不超过 0.001 才接受，随后归一化。不从欧拉角重算四元数。
- 默认拒绝 `age_ms > 500` 或未知年龄 `65535` 的导航更新。最近有效结果的年龄还随 PC 单调时间增加，不能缓存为永久有效。
- 默认 100 ms 没有新有效测量历元即断流。相同序号或时间戳均不更新位姿、速度或导航新鲜度。
- 默认 3 s 没有任何校验成功的帧则关闭端口并重连。无效状态帧可以保持在线，但不会保持导航可用。
- 模拟帧始终保留原始模拟标志。默认 `allow_simulated=false`，不用于位姿输出；联调脚本显式启用。

`packet_seq` 的无符号差为零视为重复，小于 `2^31` 的非零差视为向前推进，差大于等于 `2^31` 视为明确回退；正常 uint32 回绕不会重启会话。明确序号回退或有效导航测量时间回退会更换 `session_id`。断开重连也更换会话、清理残包和四元数连续性基准。v1 没有板卡会话号，不能保证识别所有重启；轨迹记录端应按 `session_id` 分段。

## 坐标算法

采用 WGS84：长半轴 `a=6378137 m`，扁率 `f=1/298.257223563`，`e²=f(2-f)`。对纬度 φ、经度 λ、椭球高 h：

```text
N = a / sqrt(1 - e² sin²φ)
X = (N+h) cosφ cosλ
Y = (N+h) cosφ sinλ
Z = (N(1-e²)+h) sinφ
p_map = R_ecef_to_enu(origin) × (p_ecef - origin_ecef)
```

`Coordinates::reverse()` 从局部坐标恢复 WGS84 经纬高，处理极点和跨 ±180° 经线。此模型适用于地表附近的导航坐标，不用于地心附近的退化大地坐标问题。

局部原点支持两种方式：

- `first_valid`：首次合格测量建立原点。默认还要求 RTK 固定解和 `GNSS_RECENT`；可设置 `origin_require_rtk_fixed=false` 放宽。RTK 状态和 GNSS 近期更新并不能证明当前导航解的具体精度。
- `fixed`：使用配置中的 `origin_latitude_deg`、`origin_longitude_deg`、`origin_height_m`。正式作业应记录首次原点并配置为 fixed，以跨进程、跨次作业复用。

同一进程中重连或板卡重启不改变原点。需要重设时停止节点，修改原点配置并重新启动。`first_valid` 模式下节点进程重启会重新建立原点。局部 Z 是原点切平面坐标，输入 h 是椭球高，均不等同于海拔。

姿态先从 Hamilton `wxyz` 四元数得到 `R_ned_frd`，然后：

```text
R_enu_ned = [[0,1,0], [1,0,0], [0,0,-1]]
R_frd_flu = diag(1,-1,-1)
R_map_ned = R_ecef_to_enu(origin) × R_ecef_to_enu(current)ᵀ × R_enu_ned
R_map_imu = R_map_ned × R_ned_frd × R_frd_flu
v_map_imu = R_map_ned × v_ned
```

这里同时处理当前位置与原点处切平面方向的差异。位置、速度和姿态属于同一个固定 ENU 坐标系，不能只将速度 N/E/D 重排后就当作任意距离下的 map 速度。输出四元数采用相邻点积处理 `q` 与 `-q` 的符号连续性。

安装外参：

- `base_link` 的控制参考点为左右差速驱动轮的轴线中点，即本车后轴中心；前轴万向轮处的导航板不是控制参考点。
- `imu_translation_in_base_m`：从后轴中心指向导航输出定位参考点的 XYZ，表达于车体 FLU，单位 m。前方为正 X、左方为正 Y、上方为正 Z；导航板位于前方时 X 通常为正。如果板卡输出已经在固件中换算到其他点，按实际输出点填写，不能重复补偿。
- `imu_rotation_in_base_wxyz`：将导航机体系完成 FRD→FLU 换轴后的向量旋转到车辆 FLU 的单位四元数。它不是未映射的传感器原始轴安装参数。
- `extrinsics_calibrated=false` 时，输出 IMU 中心位姿，状态中的 `pose_child_frame=navigation_imu`。
- 外参标定且设为 true 后，`R_map_base=R_map_imu × R_base_imuᵀ`，`p_map_base=p_map_imu-R_map_base×t_base_imu`。

速度始终属于 IMU 中心。协议没有角速度，无法进行 `ω×杆臂` 的精确控制点速度补偿。无论是否标定，`velocity_point_frame` 都为 IMU。姿态以四元数为准，RPY 只保存在原始消息中供诊断。

## ROS 输出和时间

所有名称为相对话题，支持 ROS 命名空间。默认世界坐标名为 `navigation_map`，避免与其他定位系统的 map 所有权混淆。

| 话题 | 类型 | 语义 |
|---|---|---|
| `navigation/raw` | `terramind_interfaces/NavigationFrame` | CRC 正确的原始帧，字段分别保持协议单位与 NED/FRD 定义；不是全字段都属于 Header 的 frame |
| `navigation/status` | `terramind_interfaces/NavigationStatus` | 约 20 Hz，在线/可用、原点、参考点、板卡标志、会话与累计统计 |
| `navigation/pose` | `geometry_msgs/PoseStamped` | ENU 中的 IMU/车辆位姿，参考点看 status.pose_child_frame |
| `navigation/imu_pose` | `geometry_msgs/PoseStamped` | 始终为未扣除杆臂的 IMU 中心位置及 IMU FLU 姿态，供辨识使用；与 pose 使用同一有效测量和时间戳，不受 extrinsics_calibrated 开关影响 |
| `navigation/velocity` | `geometry_msgs/Vector3Stamped` | 固定 ENU 中的 IMU 中心线速度，单位 m/s |
| `diagnostics` | `diagnostic_msgs/DiagnosticArray` | 串口、数据有效性和错误统计 |

原始帧、位姿和速度采用 SensorDataQoS（best effort、volatile、深度 5），状态 reliable、volatile、深度 1。位姿/速度仅在新鲜有效的新历元产生时发布，故障时不重复广播旧结果。`status.usable` 表示板卡导航测量可用，`origin_ready` 表示坐标输出条件就绪；使用 pose 的上层同时检查二者。状态中的 nav_valid、RTK、GNSS 等字段及 age_ms 是最后收到的报文字段，不代表持续更新的精度或年龄，是否可继续使用以 usable 为准。

所有 Header 时间戳均为 PC 接收处理时的 ROS 时间，`stamp_reference=receive_time`。板卡 `state_time_s` 单独保留，不是 UTC/Unix 时间；`TIME_LOCKED` 也不代表 PC 已与板卡同步。`age_ms` 不含 DMA/链路延迟，本版不将接收时间伪装成精确测量时间。用于多传感器融合前需要补充时间映射及其误差模型。

本版不发布动态 TF、不填造协方差、角速度或加速度，不把板卡融合经纬度冒充原始 GNSS，不替代轮式里程计或 PC 端状态估计。坐标约定参考 [REP-103](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0103.rst)，未来接入坐标树遵循 [REP-105](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0105.rst)。

## 后轴偏移配置与两圈自转辨识

当前 `navigation.yaml` 已保存本车 2026-10-27 的标定：`imu_translation_in_base_m=[0.37256543143110654,-0.003113059886865596,0.1]`，安装旋转为单位四元数，`extrinsics_calibrated=true`。X/Y 来自正反自转拟合，独立整圈验证的中心位置 RMS 为 0.02049 m；Z=0.10 m 及前向朝车头、水平安装由用户确认。这些参数描述当前安装，换车或改变安装后需重新确定。

本车固件正角速度使车体顺时针转，`serial.yaml` 因此设置 `angular_command_sign: -1`。真实串口驱动在下发命令和发布底盘角速度反馈时统一换算；ROS 话题仍以逆时针为正，轮速保留固件原始符号。参数只允许 +1/-1，节点自身默认 +1，仿真和虚拟串口入口不加载本车的反向配置。面板及标定脚本不得再额外反转角速度。

打开真实控制板和导航的区域作业面板：

```bash
ros2 launch terramind_bringup real.launch.py navigation:=true panel:=true panel_page:=coverage
```

启动只执行未使能零指令握手，区域作业仍需用户建区、生成并启动。若已量得新的前后、左右、高度差，可以填写 `imu_translation_in_base_m`，核对安装旋转后将 `extrinsics_calibrated` 改为 true；重启导航后，自动作业读取的 `navigation/pose` 就是后轴中心位姿。

也可以用 `calibrate_lever_arm` 自动识别水平 X/Y。程序使用实测航向反馈完成逆时针一圈、停稳、顺时针一圈、停稳；默认角速度 0.4 rad/s，线速度为零，所有机具关闭。升降关闭沿用现有控制协议，会回零。控制与导航后端需要已启动，控制面板及其他命令发布工具必须关闭，程序复用同一套 Stop→Enable 握手、50 Hz 完整指令及 150 ms 看门狗。

在实际 Linux 主机上，以同一份导航配置启动后端和辨识程序（两条命令分别在两个终端运行）：

```bash
ros2 launch terramind_bringup real.launch.py panel:=false navigation:=true \
  navigation_config:=/绝对路径/navigation.yaml
ros2 run terramind_panel calibrate_lever_arm \
  --config /绝对路径/navigation.yaml \
  --output /绝对路径/navigation-identified.yaml
```

导航串口默认自动发现，也可在配置中填写显式路径；控制板沿用已有自动发现或显式 `device`。`--speed` 可设 0.15～0.6 rad/s。辨识前至少有 0.5 秒稳定定位，需要近期 GNSS 更新、RTK 固定解和水平地面（车体倾角不超过 5°）；尚未启用外参也能辨识。程序核对运行中驱动的安装外参是否与 `--config` 一致，防止用错安装角。Ctrl+C、导航失效、数据过期、会话/原点/控制板连接变化或控制源冲突都会停止，本次结果不保存，也不会自动恢复。

拟合模型是 `p_imu_xy = c_turn + R(yaw_base) × [tx, ty]`。两圈分别估计转心，再比较杆臂；允许圈间转心小幅变化。每圈至少 60 个有效样本且覆盖几乎整圈，按角度均衡加权。每圈位置残差 RMS 不得超过 3 cm，单点残差不得超过 12 cm，两方向杆臂差不得超过 4 cm；不满足则报告失败。滑移和 GNSS 系统误差仍可能影响实际精度，仿真误差不是现场精度承诺。

平面自转不能同时辨识安装角和车体杆臂，也不能辨识高度。因此先按实际安装填写 `imu_rotation_in_base_wxyz`；默认单位四元数只适用于完成 FRD→FLU 后与车体轴对齐的安装。输出文件更新 X/Y，保留输入配置的 Z 和安装旋转，附带残差、正反差异及样本数。它不覆盖已有文件，也不修改运行中的导航参数；输出保留 `extrinsics_calibrated: false`，确认 Z 和安装旋转后改为 true，使用新配置重启导航。这样不会把仅完成平面识别误标为完整外参已确认。

无硬件验证可直接运行：

```bash
ros2 run terramind_panel lever_arm_integration_test.py
```

该测试自建私有二维底盘、前置定位点、200 ms 延迟和导航 PTY，运行真实辨识命令，核对正反两圈、结果文件、后轴补偿与失效停机；无需启动其他仿真节点，也不会打开真实串口。

## 验证

```bash
colcon test --packages-select terramind_navigation_driver terramind_transport
colcon test-result --verbose
ros2 run terramind_navigation_driver navigation_integration_test.py
ros2 run terramind_navigation_driver navigation_discovery_integration_test.py
```

单元测试核对文档原始 80 字节向量（CRC `0x233D`）和标准 CRC（`0x29B1`），覆盖所有分包位置、载荷内帧头、坏版本/CRC、残帧超时、噪声上界、无效标志/数值、年龄、重复历元、回绕/重连、姿态换轴和杆臂方向。

位置独立参考由本机 PROJ `cct` 生成，未调用被测公式：

```bash
printf '114.000123 30.000234 52.3 0\n' | cct -d 12 +proj=pipeline \
  +step +proj=cart +ellps=WGS84 \
  +step +proj=topocentric +ellps=WGS84 +lat_0=30 +lon_0=114 +h_0=50
```
