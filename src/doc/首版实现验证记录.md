# 首版实现验证记录

验证日期：2026 年 9 月 30 日。环境：Ubuntu 22.04、ROS 2 Humble。

| 验证内容 | 结果 |
|---|---|
| 八个 ROS 包构建与安装 | 通过 |
| 19 个 GTest 用例 | 全部通过 |
| 独立 Python 字节流测试连接 C++ 控制板模拟器 | 通过 |
| ROS 直接仿真进程测试 | 通过 |
| ROS 真实串口节点连接虚拟控制板的进程测试 | 通过 |
| sim.launch.py 与文档中的 control_cli.py | 实际启动、运动、停止通过 |
| serial_test.launch.py 与文档中的 control_cli.py | 实际启动、运动、停止通过 |
| 机器人 URDF 生成、robot_description 与 joint_states | 通过 |
| real.launch.py 启动参数解析 | 通过，未连接真实硬件 |

GTest 的 19 个用例分别为协议 7 个、串口 2 个、指令保护 4 个、连接会话 2 个、仿真模型 4 个。colcon 汇总的 24 项还包含 5 个 CTest 包装项，并非 24 个不同的 GTest 用例。

ROS 进程测试覆盖底盘运动、播撒与刀盘设定、独立指令过期、软件停止锁定、非法速度、未支持升降请求、丢失状态、控制板模拟器重启，以及控制管理进程被强制结束后的后端独立停机。补充用例确认传输延迟会消耗指令有效期。

运行环境限制了 UDP 网络接口访问，测试时 DDS 有相关日志；本机节点间的数据与服务断言均已通过。本次不能据此证明跨主机 ROS 网络通讯可用。

未验证：真实 USB 串口与控制板、实际电机方向和反馈口径、机械停机距离、物理急停、RViz 窗口的视觉效果。RViz 启动配置和模型已提供，窗口未做图形验收。Gazebo 与组合导航板尚属后续阶段。

## 控制面板增量验证

同日新增 `terramind_panel`（PyQt5 / rclpy），工作区扩展为九个包，构建与安装通过。原有 19 个 GTest 和新增 12 个 Python 字段范围/能力测试通过。`colcon test-result` 汇总为 37 项，包含 6 个 CTest 包装项。

| 验证内容 | 结果 |
|---|---|
| Qt 面板 → 控制管理 → 二维仿真，全部能力 `0x003F` | 通过 |
| Qt 面板 → 控制管理 → 真实串口驱动 → 私有 PTY 模拟板，全部能力 `0x003F` | 通过 |
| 默认 `0x000F` 能力下升降和喷洒字段禁用 | 通过 |
| 草稿/应用、全字段目标、关闭装置归零、停止和撤销使能 | 通过 |
| Qt 事件循环冻结、状态丢失、模拟板重连、关闭窗口 | 停机且不自动恢复，通过 |
| 服务无响应后恢复、停止与使能交错、其他控制源接入 | 通过 |
| 一键仿真带面板、串口联调带面板、单独面板、无图形模式启动和退出 | 通过 |
| 控件布局、中文标签、能力禁用显示 | 已渲染无显示 Qt 窗口并检查截图 |

进程测试在独立 ROS 域内运行，仅使用模拟后端。测试发现沙箱禁止本地 socket 写入，导致 ROS 启动器的退出通知可能延迟；同样的启动和交互测试在正常运行环境中全部通过。面板启动过程先等待一次停止服务确认，再发送使能请求，避免服务暂停期间积压的停止请求打断新一轮使能。

真实串口驱动已通过 PTY 链路验证，但没有连接实际 USB 控制板，真实执行器和机械反馈尚未验收。

## 自动串口发现增量验证（2026 年 10 月 1 日）

真实串口默认改为 `device=auto`，先监听候选设备的 v1 状态帧，再对唯一匹配执行零指令握手。九个包构建通过；新增 6 个发现测试，包括设备别名去重、协议状态完整性与序号/uptime 回绕、无发送筛选、多板卡歧义、重复状态不能续期、占用锁及取消扫描。25 个 GTest 与 12 个 Python 用例全部通过；colcon 汇总 44 项包含 7 个 CTest 包装项。

`serial_discovery_test.py` 使用私有虚拟串口完成：无设备等待、导航文本过滤且未收到控制字节、同一板卡多个路径去重、两块匹配板卡不自动选择、移除其中一块后自动连接、完整握手及运动控制、拔插后端口从 ttyUSB1 变为 ttyUSB9，以及连接恢复后保持停机。

原有手动端口的 `ros_smoke_test.py --mode serial` 和 `panel_integration_test.py --mode serial` 回归通过。实机 launch 参数解析确认默认 `device=auto`。未打开实际 USB 串口；真实板卡是否按协议在控制接管前持续上传状态，还需接板确认。
