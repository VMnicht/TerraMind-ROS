# 联调与测试说明

测试分为纯逻辑、独立字节流和 ROS 进程三层。所有自动测试使用内存模型或 PTY，不打开物理 USB 串口。

## 纯逻辑测试

在已完成构建的工作区根目录执行：

```bash
source /opt/ros/humble/setup.bash
source install/local_setup.bash
export ROS_LOG_DIR="$PWD/log/ros"
colcon test --event-handlers console_direct+
colcon test-result --verbose
```

`colcon test` 执行 CMake 登记的 GTest 和 pytest；下面的字节流/ROS/Qt 集成脚本还需单独运行。修改消息定义或 C++ 后先重新构建，避免测试旧产物。

- protocol_test：XMODEM 标准向量、文档全零帧、任意分块、噪声、坏 CRC、坏长度、未知和重复 TLV、非有限数值、控制/状态编码。
- transport_test：实际 PTY 读写、端口建议锁、无效设备及波特率。
- guard_test：禁用握手、连接代次、有效期与传输延迟预算、停机锁定、非法数值/时间戳。
- session_test：零指令确认、重复状态、过旧接纳序号、重启和帧序号回绕。
- discovery_test：字符设备别名去重、多帧识别、序号/运行时间回绕、候选无写入、多板歧义、重复帧失效、锁占用和取消。
- model_test：控制权接管、250 ms 超时、错误命令不续期、整帧拒绝、作业停止与差速运动。
- panel_controls：完整草稿、关闭归零、非法数值、底盘和作业能力限制。
- debug_launcher：子进程及孤儿进程组回收、参数引用、任务互斥、构建成功后启动、日志与退出。

## 独立字节流验证

`ros2 run terramind_sim serial_loopback_test.py` 使用 Python struct 和 binascii 独立生成/读取协议，不调用 C++ 编解码库，降低驱动和模拟器因共用错误编解码而互相验证通过的风险。它创建临时 PTY，验证分片、未知 TLV、序号回绕、CRC 错、越界值、不支持外设、重复 TLV、停止以及下位机超时。

## ROS 进程验证

`ros2 run terramind_sim ros_smoke_test.py --mode sim` 验证直接仿真；`--mode serial` 验证实际串口节点连接 PTY 模拟器。测试启动独立 ROS 域和私有进程，检查标记为 simulated 的状态后才会请求使能。

覆盖默认停机、健康握手、底盘运动、作业装置、各输入独立过期、停止锁定、无重新使能时不得自动恢复、非法控制、状态链路丢失或板卡模拟器重启，以及控制管理进程被强制终止后的后端独立停机。

`serial_discovery_test.py` 使用私有 PTY 路径作为候选集，覆盖没有设备、无关导航文本、设备别名、多块模拟板歧义、单板接入和拔插后编号变化。不会对 `/dev/ttyUSB*` 做实机扫描。

```bash
ros2 run terramind_sim serial_loopback_test.py
ros2 run terramind_sim serial_discovery_test.py
ros2 run terramind_sim ros_smoke_test.py --mode sim
ros2 run terramind_sim ros_smoke_test.py --mode serial
```

## Qt 面板和调试启动器

`panel_integration_test.py` 操作真实控件验证草稿/应用、关闭归零、使能过程停止、服务超时、界面阻塞后的独立停机、连接更换和控制源冲突。模拟能力参数可为 15（旧板卡）、47（当前含喷洒）或 63（全部装置）。

```bash
QT_QPA_PLATFORM=offscreen ros2 run terramind_panel panel_integration_test.py --mode sim --capabilities 63
QT_QPA_PLATFORM=offscreen ros2 run terramind_panel panel_integration_test.py --mode serial --capabilities 47
QT_QPA_PLATFORM=offscreen ros2 run terramind_panel panel_integration_test.py --mode sim --capabilities 15
QT_QPA_PLATFORM=offscreen ros2 run terramind_panel debug_launcher_integration_test.py
```

总面板集成测试使用真实 ROS 子进程检查启动、互斥、停止及进程组清理；实机入口只指定一个不存在的端口，验证命令行端口覆盖 auto，不打开真实板卡。离屏测试不验证物理鼠标、桌面窗口管理或 USB 硬件。

调试总面板中也可以选择上述测试。测试会创建/销毁子进程和临时 PTY，执行前先停止当前调试任务。出现 DDS 网卡或 socket 权限错误时应检查执行环境限制，不能据此推断通讯协议失败。

## 人工仿真故障注入

在 sim.launch.py 运行时：

```bash
ros2 service call /sim/drop_commands std_srvs/srv/SetBool '{data: true}'
ros2 service call /sim/drop_commands std_srvs/srv/SetBool '{data: false}'
ros2 service call /sim/drop_status std_srvs/srv/SetBool '{data: true}'
ros2 service call /sim/drop_status std_srvs/srv/SetBool '{data: false}'
ros2 service call /sim/reset std_srvs/srv/Trigger '{}'
```

故障解除后需要重新使能。模拟器停止目标不代表物理模型的实际速度瞬时归零，模型保留减速过程。

## 现场联调待办

先核对接口电平、USART3 引脚、115200 8N1 和设备路径，再确认零快照接纳以及 喷洒板卡 capabilities=0x002F（旧板卡 0x000F 保持兼容）。首次合法快照会接管 USART3，停机也不会退回 UART5。

逐项核对实际底盘前进和正角速度方向、左右播撒方向、刀盘油门设定、喷洒开关与 0～100% 目标，以及状态中的实际 RPM 含义。喷洒反馈需要同时核对目标、actual_percent 与 feedback_valid 的固件来源；没有有效反馈时不能将目标值视为实测值。填写真实轮径、轮距和必要减速比。逐项测量上层停止发布、串口拔出、板卡重启和 PC 退出后的响应；最后才对接后续自动任务。

软件测试不证明真实 USB 驱动、电气接口、电机执行和物理急停已验证。协议引用的固件源码及 tools/pc_protocol.py 不在本工程中，模型与真实固件的边界行为仍应交叉核验。
