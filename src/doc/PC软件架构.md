# PC 软件架构

当前采用九个包。控制管理节点只有一个完整快照输出，实际串口和直接仿真后端互斥启动。机械结构按双轮差速处理，线速度和角速度由 PC 下发，真实左右轮速度分配由下位机执行。

| 包 | 边界 |
|---|---|
| terramind_interfaces | ROS 消息定义，完整保留系统、底盘及作业装置字段 |
| terramind_protocol | 不依赖 ROS 的 C++ 字节编解码、CRC、流式分帧和数值校验 |
| terramind_transport | 不认识控制协议的 Linux 串口读写，支持 PTY |
| terramind_control | 上层指令汇总与有效期检查；导出后端使用的独立指令保护库 |
| terramind_mcu | 控制板连接会话、握手、序号确认、ROS 状态转换和真实串口节点 |
| terramind_sim | 控制板行为模型、二维差速模型、ROS 直接仿真与字节级模拟器 |
| terramind_description | 参数化 URDF 文本模板、RViz 配置 |
| terramind_panel | PyQt5 原生控制面板；完整目标编辑、发送与反馈显示，复用现有控制接口 |
| terramind_bringup | 三种启动入口和集中配置 |

代码使用 C++17；串口节点用一个独立工作线程进行有界读写。ROS 消息回调不等待串口操作。串口发送不维护旧指令队列；每个周期获取最新完整快照。部分写入必须在有限期限内完成，失败则关闭连接，避免拼接两条控制帧。

## 数据链路

`terramind_panel` 作为单个上层控制源，接入下列链路。`controls.py` 定义可控字段与范围，`controller.py` 负责 ROS 状态与发送会话，`window.py` 负责 Qt 草稿编辑及反馈展示。Qt 定时器在同一线程调用 ROS 回调和发送，保证界面冻结时不会继续刷新旧指令。面板每 20 ms 发布带新时间戳的完整输入，开始发送前调用使能服务，收到控制状态确认后才下发非零目标。

`cmd_vel + implements/command + enable/stop → control_manager → mcu/command → 后端 → mcu/state`

真实后端：`mcu_serial_node → SerialPort → USB 串口 → 下位机`。

直接仿真：`sim_interface_node → BoardModel → DifferentialDriveModel`。

虚拟串口：`mcu_serial_node → PTY → serial_board_emulator → 同一个 BoardModel`。

BoardModel 共享控制权、能力、拒绝命令、看门狗及状态语义，ROS 直接仿真不重复实现这部分行为。帧序号属于后端，与上层业务消息解耦。仿真器的数学运动与设备反馈生成仍是近似模型，不能替代真实固件交叉验证。

## 控制与连接状态

真实驱动默认 `device=auto`。`port_discovery` 按配置的 glob 路径枚举字符设备，按设备号消除 `/dev/serial/by-id` 与 `ttyUSB` 等别名重复；只在未连接时打开并监听候选端口，不向未识别的设备发送报文。候选端口共享一个有界监听窗口，需观察到多帧 CRC/TLV 正确、状态序号和 uptime 向前推进的数据，且在窗口结束时仍新鲜。扫描结果恰有一个匹配才接入，多个匹配则保留未连接状态并报告路径。

扫描与正常通讯运行于同一个串口工作线程。选中的句柄从识别到控制会话一直保持打开和加锁，不按端口名称重新打开，避免探测后设备名称被重分配的问题；清空探测缓存后再进入正常零指令握手。断连时释放句柄、锁定停机并重新扫描。手动 `device` 路径绕过发现步骤，保留原有握手行为。未来导航驱动复用串口库的占用锁，避免与扫描器同时读取同一设备。

上位机启动为未使能。真实串口打开后发送全零未使能快照，观察回传序号、接纳结果、模式、故障和命令年龄，确认后才报告链路就绪。20 ms 下发与约 50 ms 回传速率不同，不期待每个控制包都有单独回执。匹配最近发送记录并核验时间，重复状态帧不能刷新链路有效期。

每次新串口连接使用随机非零 connection_id，控制管理节点把它带入完整快照；旧连接的指令直接丢弃。状态中的 uptime 明显回退视为板卡重启；正常 uint32 回绕单独处理。断线后重新零指令握手，控制管理节点撤销使能并丢弃输入缓存。

上层有效期和后端有效期均默认 150 ms，使用单调时钟。消息还检查 ROS 时间戳，拒绝过期、过度超前或倒序的控制数据。传输延迟从有效期中扣除，不会在接收时把旧指令的有效期重新延长一遍。初始使能后允许最多一个有效期等待新 cmd_vel；即使只运行作业装置，也需持续发布零速度心跳。已经打开的作业装置还必须独立持续刷新 implements/command。服务幂等重复使能不会延长输入有效期。

后端指令保护在超时或故障后锁定停机，需要先收到未使能快照，再接收新的使能快照。正常管理节点恢复会先输出未使能快照，并等待用户重新使能。因此单纯恢复指令发布不会自动恢复运行。

停止和使能服务确认的是 PC 的请求处理，不是设备执行 ACK。设备接纳由 McuState 报告。CRC 正确但语义非法的指令会更新最近控制序号和 result，但不会续期 BoardModel 看门狗。TIMEOUT=4 保留；超时按协议只通过故障位表示。

## 时钟与坐标

MVP 全部使用真实时间，不发布 /clock；节点显式拒绝 use_sim_time=true。后续接入 Gazebo 时必须补充仿真暂停、时间回跳和重新使能策略。当前提供显式 sim/reset 服务，复位后更换 connection_id，清空运动和控制状态。

仿真真值发布到 /sim/ground_truth，参考坐标为 sim_world；同一节点发布 sim_world → base_link。robot_state_publisher 发布模型关节变换。真值不冒充融合定位或传感器测量，当前没有 /odom、map → odom 或真实里程计。

## 后续扩展

组合导航板增加 terramind_navigation_driver 包，复用串口库，独立定义协议解析，按实际板卡能力发布 GNSS、IMU 或定位结果。

轮式里程计和导航融合增加 terramind_state_estimation 包。在实际轮径、轮距、RPM 轴侧、减速比和反馈有效性明确前，不对真实 RPM 做未经确认的换算。

Gazebo 接入保留控制消息、控制板模型和状态接口，用物理引擎替换 DifferentialDriveModel；额外传感器以标准 ROS 消息发布。当前工程未安装或编写 Gazebo 集成。
