# 实物差跟踪演示

这是有意注入横向参考偏置的实车演示，不是正常控制器的历史缺陷或真实性能评价。显示的红色轨迹来自真实导航数据，数据和截图都标注故障注入。正常源码、参数和现有纯仿真演示不受影响。

## 启动

先运行正常的实机控制板与导航后台，关闭普通控制面板，再执行：

```bash
./start_physical_tracking_demo.sh
```

此命令只打开演示面板。现场确认空间和急停后，在面板正常建区、生成路线、开始作业。区域固定为 2×2 m、割幅 27 cm。`--run-once` 会通过同样的正常建区和启动检查执行一次完整路线并退出；只有现场已准备好且明确要开始运动时才使用。

点击开始后默认倒计时 10 秒，面板顶部可调为 0～120 秒，也可用 `--start-delay 10` 设置初始值。倒计时期间不使能、不发运动指令；可以点击“取消倒计时”或“停止全部”取消。关闭面板、定位失效、连接或路线改变、界面响应超时都会取消，恢复后需要重新点击开始。倒计时结束仍执行原有完整启动检查。

演示在覆盖直线中段加入最大 12 cm 横向参考偏置，起步、到位、换行和返航使用正常控制。始终禁用刀盘、升降、喷洒和播撒；线速度指令上限 0.10 m/s、角速度上限 0.60 rad/s，真实横向偏差超过 18 cm 或越过外部空间边界时停机，单次任务最长 450 秒。原有定位有效性、静止建区、启动位姿、控制源冲突和失联停机检查保留。

当前实机速度换算尚有误差，指令速度不等于真实地速；此前 0.10 m/s 指令对应约 0.17 m/s 实测直行速度。需保持整块区域及外围至少 0.5 m 空旷，并有人能随时急停。

关闭演示面板后，重新打开原控制面板即可使用正常程序，不需恢复参数文件。不要同时打开两个实车控制面板。

## 记录

每次运行的真实位姿、目标速度、车轮转速、导航状态和结果保存在 `log/physical-tracking-demo/<时间>/`，包含 `metadata.json`、`plan.json`、`telemetry.json`、`result.json` 和 `physical-demo.png`。不要把故障注入记录标作正常模式或历史版本的实测记录。

可在停止后生成实测轨迹和横向误差图：

```bash
python3 demos/physical_tracking_demo/plot.py log/physical-tracking-demo/<时间>
```
